# VECTIS v0.2.0

VECTIS 0.2.0 establishes structured mission state and durable public project contracts while preserving deterministic planning and explicit authority.

## Language and values

The value model includes strings, numbers, booleans, deterministic lists, deterministic objects, and unknown runtime values.

Lists and objects use pure construction and access functions. Nested structured values can flow through declarations, computed values, assertions, conditions, publications, execution reports, and structured CLI output.

```vectis
mission "Structured release state" {
    source build object(
        "passed", true,
        "coverage", 94,
        "checks", list(true, true, true)
    );

    let approved get(build, "passed")
        && get(build, "coverage") >= 90
        && all(get(build, "checks"));

    assert approved, "Build readiness requirements were not met";

    publish object(
        "status", if_else(approved, "AUTHORIZED", "REVIEW"),
        "coverage", get(build, "coverage")
    );
}
```

## Structured functions

| Function | Contract |
| --- | --- |
| `list(...)` | Construct an ordered deterministic list. |
| `object(...)` | Construct an object from alternating string keys and values while rejecting duplicate keys. |
| `get(...)` | Read an object key or list index with an optional default. |
| `has(...)` | Test whether an object key or list index is available. |
| `keys(...)` | Return object keys in deterministic construction order. |
| `values(...)` | Return object values in deterministic construction order. |
| `size(...)` | Measure a string, list, or object. |
| `all(...)` | Evaluate a list of booleans as an all gate. |
| `any(...)` | Evaluate a list of booleans as an any gate. |

## Explainable assertions

Assertions may include a deterministic failure explanation.

```vectis
assert quality >= 90, "Quality score must be at least 90";
```

The message becomes runtime failure context. It does not alter the assertion condition, scheduling, graph dependencies, or capability model.

## Compatibility and governance

The repository defines compatibility rules in `COMPATIBILITY.md`. Durable grammar, semantic, graph, runtime, serialization, authority, and public API changes use the RFC process in `docs/rfcs/README.md`.

Patch releases in the 0.2 line preserve documented 0.2 contracts except where a security correction requires restriction.

## Public history integrity

The public repository starts from a sanitized VECTIS root. The quality gate audits the current tree, reachable refs, commit messages, and reachable historical file contents for retired private labels.

## Security and authority

Structured values remain data. They do not grant filesystem, process, HTTP, environment, or other external authority.

Capability checks, bounded adapters, no implicit shell execution, no host-language dynamic evaluation, and explicit execution planning remain part of the VECTIS security contract.

## Compatibility

VECTIS 0.2.0 supports Python 3.11 through 3.14. Release artifacts are built and installed in an isolated environment during validation.
