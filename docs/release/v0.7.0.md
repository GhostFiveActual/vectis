# VECTIS v0.7.0

VECTIS 0.7.0 makes explicit actions directly usable from command-line execution surfaces through opt-in local authority profiles.

## Explicit profile selection

```bash
vectis actions --config actions.toml
vectis run --actions-config actions.toml mission.vectis
vectis mission --actions-config actions.toml mission.vectis
vectis timeline --actions-config actions.toml mission.vectis
vectis report --actions-config actions.toml mission.vectis
```

VECTIS does not search the working directory, project manifest, environment, or user home directory for an action profile. A profile participates in execution only when its path is supplied explicitly.

## Filesystem authority

Filesystem roots may be absolute or relative to the selected profile. They continue through canonical root confinement and symlink escape checks.

## Process authority

Process profiles use explicit executable aliases mapped to absolute executable paths. Structured arguments, timeout ceilings, `shell=False`, and disabled parent-environment inheritance remain part of the process contract.

Only environment key/value pairs written in the selected profile are supplied to the child process.

## HTTP authority

CLI HTTP profiles require a non-empty hostname allowlist. Host matching is exact after normalization. Existing HTTP/HTTPS scheme checks, embedded credential denial, proxy isolation, redirect denial, and bounded timeouts remain in force.

## Inspection

`vectis actions` displays standard action contracts without registering or granting them.

`vectis actions --config FILE` validates a selected profile and returns its configured capabilities, operations, filesystem roots, executable aliases, environment key names, allowed HTTP hosts, and timeout boundaries. Environment values are not displayed.

## Plan audit

Action nodes contribute their declared capabilities to the required authority footprint returned by `vectis audit`. The audit also identifies each action operation and its capability without invoking external work.

## Project scaffolding

`vectis init` writes an inert `actions.example.toml` beside the project manifest. The example is not loaded automatically.

## Compatibility

Existing VECTIS source behavior remains intact. The 0.7 patch line preserves explicit profile selection, bounded adapter contracts, exact action-to-capability validation, process executable requirements, HTTP host allowlists, and redacted profile inspection.

## Design record

RFC 0004 records the profile format, authority model, inspection contract, security boundaries, compatibility commitments, rejected alternatives, and regression strategy.

## Verification

Release verification covers profile parsing, unknown section rejection, filesystem root resolution, absolute process executable validation, HTTP hostname allowlists, redacted manifests, CLI execution, action-aware plan audits, project scaffolding, repository policy, reachable-history privacy checks, package builds, isolated wheel checks, and Python 3.11 through 3.14.
