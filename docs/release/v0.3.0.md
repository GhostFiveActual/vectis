# VECTIS v0.3.0

VECTIS 0.3.0 introduces reusable deterministic computation through top-level user-defined pure functions while preserving the execution graph, runtime, and authority model established by earlier language lines.

## Pure functions

A function declares an explicit parameter list and one returned expression.

```vectis
function release_ready(score, risk) {
    return score >= 90 && risk <= 25;
}

function release_summary(score, risk) {
    return object(
        "approved", release_ready(score, risk),
        "score", score,
        "risk", risk
    );
}
```

Functions may return scalar or structured values and may call deterministic built-ins or other user-defined pure functions.

## Scope and authority

Function parameters form the complete local reference environment for the function body.

A function cannot capture source, let, analyze, stage, mission, capability, process, filesystem, HTTP, environment, or runtime handler state.

Function declarations produce no execution nodes and cannot acquire capabilities.

## Call graph

Functions may call functions declared earlier or later in the file. Semantic analysis constructs the user-function call graph before graph generation.

Direct recursion and indirect recursive cycles are rejected.

## Compilation

User-function calls are expanded during compilation. The expanded expression becomes the executable graph expression and participates in ordinary dependency discovery, constant evaluation, graph fingerprinting, plan limits, reporting, and runtime evaluation.

When expansion changes the expression, graph metadata retains the authored call as `source_expression` and the executable form as `expression`.

## Type behavior

Function result types participate in semantic checking when they can be inferred from the function body.

A comparison-returning function can serve as a condition. A function that deterministically returns text is rejected when used as a boolean condition.

## RFC and compatibility

[RFC 0001](../rfcs/0001-pure-functions.md) defines the function contract, scope model, recursion rule, compilation model, authority boundary, alternatives, and verification requirements.

The [compatibility contract](../../COMPATIBILITY.md) defines the 0.3 patch-line guarantees. Valid 0.2 mission syntax remains valid in 0.3.

## Packaging

CI validates Python 3.11, 3.12, 3.13, and 3.14. The isolated wheel test executes a mission that calls a user-defined function, proving that the parser, semantic analyzer, compiler expansion, runtime, structured values, formatter, CLI, and packaged assets ship together.

## Public history integrity

The public-tree and reachable-history audit remains part of the release quality gate. Release tags are created only after that audit and the complete repository quality gate succeed.
