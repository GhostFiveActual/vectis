# VECTIS Experience Standard

## Purpose

VECTIS is memorable when users can see what their intent becomes. Product surfaces expose execution state instead of hiding it.

## Experience hierarchy

| Surface | Role |
| --- | --- |
| GitHub | Explain the product and get a visitor to a successful mission quickly. |
| `vectis mission` | Human operator execution view. |
| `vectis run` | Structured execution interface for tools and integrations. |
| Mission Control Studio | Visual authoring, topology, telemetry, diagnostics, and inspection. |
| Launch Control | Demonstrate VECTIS embedded inside another application through a multi-gate flight decision. |
| Showcase mission | Demonstrate a complete multi-gate workflow with a detailed execution trace. |
| HTML execution report | Produce a portable operator-facing record of graph statistics, node state, values, failures, and published results. |

## Product rules

1. Keep the official slogan visible on public product surfaces.
2. Make real execution state more prominent than decorative effects.
3. Preserve machine readable commands when adding human presentation.
4. Show branch selection, blocked work, skipped work, resolved values, and failures when they explain the result.
5. Use Abyssal Teal as the primary product accent.
6. Keep VECTIS visually dominant within the Ghost Five product lockup.
7. Use operational language only when it maps to real product behavior.
8. Avoid generic terminal aesthetics that do not communicate system state.
